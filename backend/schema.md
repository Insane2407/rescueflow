# FlowRescue Database Schema

This document outlines the database tables required to track workflows, their individual steps, and the AI diagnostic records. It is designed for PostgreSQL and can be managed via Supabase.

## Table: `workflows`
The core table representing a single tracked pipeline.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | Primary Key, Auto-generate | Unique identifier for the workflow. |
| `name` | `VARCHAR(255)` | Not Null | Human-readable name (e.g., "Order #1024"). |
| `current_step` | `VARCHAR(50)` | Not Null | Tracks the active step (e.g., "INVOICE"). |
| `status` | `VARCHAR(50)` | Not Null | Enum: `HEALTHY`, `FAILED`, `RECOVERING`, `PAUSED`. |
| `created_at` | `TIMESTAMP` | Default: `now()` | When the workflow tracking started. |
| `updated_at` | `TIMESTAMP` | Default: `now()` | Last state change. |

---

## Table: `workflow_steps`
Tracks the individual components/stages within a specific workflow pipeline.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | Primary Key, Auto-generate | Unique identifier for the step record. |
| `workflow_id` | `UUID` | Foreign Key (`workflows.id`) | Links the step to its parent workflow. |
| `step_name` | `VARCHAR(50)` | Not Null | E.g., `ORDER`, `PAYMENT`, `INVENTORY`, `INVOICE`, `SHIPPING`. |
| `status` | `VARCHAR(50)` | Not Null | Enum: `PENDING`, `COMPLETED`, `FAILED`. |
| `error_context` | `JSONB` | Nullable | Captures specific error details dumped by external systems (e.g., missing API tokens, HTTP 500s). |
| `started_at` | `TIMESTAMP` | Nullable | When the step began processing. |
| `completed_at`| `TIMESTAMP` | Nullable | When the step finished or failed. |

---

## Table: `diagnoses`
Stores the results of the LLM's analysis when a workflow step fails.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | Primary Key, Auto-generate | Unique identifier for the diagnosis. |
| `workflow_id` | `UUID` | Foreign Key (`workflows.id`) | The workflow that encountered the error. |
| `step_id` | `UUID` | Foreign Key (`workflow_steps.id`) | The specific step that failed. |
| `llm_analysis`| `TEXT` | Not Null | Human-readable explanation generated by AI (e.g., "Invoice generation failed because..."). |
| `confidence` | `FLOAT` | Not Null | Score from 0.0 to 1.0 indicating LLM certainty. |
| `recovery_plan`| `JSONB` | Not Null | Ordered array of recovery steps: `["Request", "Validate", "Retry", "Resume"]`. |
| `created_at` | `TIMESTAMP` | Default: `now()` | When the diagnosis was completed. |

---

## Indexing Strategy
- Index on `workflows.status` for quick filtering of active vs. failed workflows.
- Index on `workflow_steps.workflow_id` for fast JOINs when fetching a workflow's full state timeline.
